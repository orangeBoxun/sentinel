# Sentinel

用 Windows UIA（UI Automation）读取任意应用的窗口标题、网址和正文，按你给自己定的规则判断，
命中之后通知 / 最小化 / 关窗 / 杀进程。

**它不是防别人的，是防凌晨一点的你自己的。** 所以设计目标不是"技术上绕不过去" —— 你是管理员，
没有什么你做不到 —— 而是**让每一次放宽都要付出一次刻意的代价**，并且让偷偷放宽留下痕迹。

详细的保护模型（谁拦谁、什么情况下会触发什么、哪些拦不住）见
[**docs/保护模型.md**](docs/保护模型.md)。

---

## 为什么读 UIA

Codex、豆包工作、DeepSeek Harness 这类应用的网页跑在**内置浏览器**里 —— 不是独立进程。
所以按进程名拦浏览器无效，网络层又看不到 HTTPS 里的标题和正文。

UIA 读的是**渲染之后的文本**（屏幕阅读器走的就是这条路）：不需要解密 TLS，也免疫 ECH / TLS 1.3。

代价是它依赖应用把内容暴露给 UIA —— 「诊断」页可以当场测出来一个应用读不读得到。

---

## 能干什么

**四种规则**（同一个目标上可以叠多条，按优先级判定）：

| 类型 | 判断依据 |
|---|---|
| 关键词 | 网址 / 标题 / 正文里包含某个词 |
| 正则 | 同上，用正则 |
| 白名单 | 命中即**放行**（用来开例外） |
| **模型监督** | **写一句人话**（比如"和游戏有关的页面"），交给大模型判断，返回违规 + 一句原因 |

**五种动作**（组合成"策略"）：通知、最小化、关窗、结束进程、记账。

**还有**：生效时间表（只在某些时段生效）、宽限期与冷却（先提醒、过几秒再动手）、
规则级"允许暂停"（工作日、周末各一套额度，周期可以是每天/每周/每月，各配次数与每次时长）。

## 它是怎么防你的

三个进程，各管一件事：

| | 干什么 | 权限 |
|---|---|---|
| **Service** | 配置的主人。所有保存都经过它，解锁令牌由它判 | SYSTEM，开机自启 |
| **Agent** | 托盘图标 + 设置窗口 + **跑监控的那个循环** | 你的身份 |
| **Watchdog** | 每分钟把服务权限改回收紧状态、服务不在就拉起来 | SYSTEM，计划任务 |

几条主要的：

- **`config.json` 是只读的** —— 你改不动，界面也改不动；能改的只有服务。
- **放宽限制要一份令牌**，而那要用**另一台设备上的私钥**签发 —— 私钥不在这台机器上。
  令牌 **24 小时有效**（从你要解锁码那一刻算起）、**用完即废**、并且**绑定整份配置**。
- **保险箱**有密码和监护人解锁码两把钥匙。服务被停超过 10 分钟、或者看门狗不再运行，
  **保险箱自动封印 —— 之后只有监护人解锁码能开**。
- **审计两份**：`logs\`（你改得动，顺手能看）和 `audit\`（服务写的，你改不动，那才是证据）。

## 装

图形安装程序（双击，会弹一次 UAC —— 装服务必须管理员）：

```
Sentinel-Setup\Sentinel.Setup.exe
```

卸载在同一个程序里（装完之后它也会出现在 Windows 的「设置 → 应用」里）。
默认**保留**配置和日志；勾一下连它们一起删。
**保险箱不在图形界面的删除选项里** —— 它的权限是安装时特意设的，删了那台机器上就再也建不回来。

命令行（管理员）：

```bash
.\installer\install.ps1 -Source <发布目录> -InstallDir E:\Sentinel
```

**前提**：这台机器要装 .NET 8 Desktop Runtime（x64）。

## 用

1. **「目标」**：挑要管的应用。可以按进程名，也可以按窗口标题正则。
   填不准就去「诊断」页选一个正在运行的窗口，点「用这个进程名」。
2. **「策略」**：命中之后干什么。
3. **「规则」**：什么样的内容算命中。
4. **「大语言模型」**：用模型监督的话，在这儿配服务商（地址 / key / 模型）。
5. **「诊断」**：配之前先测 —— 读不读得到、规则链哪一环断了，它会把每一步摊开。
6. **「概览」**：开监控。**解锁保护**也在这儿开。

第一次打开是**安全模式**（只记录、不动手）—— 先让它跑几天，看它都会命中什么，再决定要不要真的动手。

## 已知边界

- **挡不住决意的管理员** —— 这是设计目标，不是缺陷。见 [保护模型](docs/保护模型.md) 开头。
- **监控的是「看得见」的窗口**：前台那一个，以及任何**露在屏幕上**的窗口。一块都没露的不读 ——
  看不见的东西影响不到任何人，读它只是白花 UIA 的时间（一次几百毫秒）。以前只读前台，
  于是摆一个小窗口压在最上面，旁边的违规视频就永远不判；这条路现在堵上了。
- **一轮最多读四个窗口**。多出来的轮着来，不会漏，最坏等几轮。
- **模型监督是异步的**：判定在后台跑，所以打开页面的第一次可能放过去，几秒后同一次浏览里会被拦。
- **模型监督按地址复用判定**：同一个网址 60 秒内沿用上一次的结论，免得页面自己一动就重新花钱。
- **模型判不出来时先放行**（等待会把监控卡住），所以那几条模型规则这时候等于不存在 ——
  **只要拿不到判定就会提醒**：本地模型没起来、模型慢到拿不到判定（一分钟没答上来）、
  被限流/欠费/被拒绝/服务端 5xx、公网连不上，全都是**每 30 秒**一次全屏，叫你换一个能用的
  模型或服务商。
  （原来"限流、欠费"那类是五分钟一次、"公网连不上"根本不提醒 —— 而那正是免费在线模型被抢光时
  会发生的事：网好好的、网站打得开、你照样能刷，只是没人判了。五分钟一次起不到任何作用。）
  **唯一不吵的是"整台机器没网"**：那时候网站自己也打不开，拦不拦没区别，为一件不会发生的事
  每 30 秒弹一次只会制造噪音。判断方式是每 30 秒（缓存）试一条公网 TCP 连接 ——
  这比问模型服务商本身准，后者连不上正是要判定的那件事。
  停摆期间**不再发新的判定请求**（判定晚到等于没有判定，而每页都挂着会把机器拖住）。
  恢复靠**探测**：每 30 秒到 2 分钟真问一次，问的是**和真实判定同一道禁令、同样大小的正文** ——
  这一点很要紧：探测如果比真实判定便宜（比如只问一句"通不通"），它就会在"其实还是慢"的时候
  报"通了"，提醒就此停掉，而真实判定照样次次超时。只有**真拿到判定**才算好了：5xx、
  回的格式看不懂，都不算。

## 开发

`tools/Sentinel.Preview` 是这套东西的离线检查工具，值得先认识它：它把真实的窗口在屏幕外跑起来、
逐页截成 PNG，另外带了十几个**端到端检查**（各自起一个隔离的服务、用临时配置，绝不碰你装好的那一套）：

```bash
tools\Sentinel.Preview\bin\Debug\net8.0-windows\Sentinel.Preview.exe --dirty-check <临时目录>
```

里面有 `--protection-check`、`--models-check`、`--supervision-check`、`--kill-check`、
`--save-check`、`--audit-check`、`--watchdog-check`、`--diag-check`、`--setup-check` 等等。

为什么值得：Agent 是单实例的，而它在你机器上正开着 —— 于是"改完看看对不对"如果只能靠装一遍，
那个循环太慢，而看不见就改等于闭着眼睛画。
